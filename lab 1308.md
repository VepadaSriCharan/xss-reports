# Cross-Site Request Forgery (CSRF) in Email Change Functionality

## Summary

A **Cross-Site Request Forgery (CSRF)** vulnerability was identified in the account email update functionality.

The application allows an authenticated user's email address to be changed through a request that does not contain effective CSRF protection. An attacker can create a forged request that changes the victim's email address and cause the request to be submitted using the victim's authenticated session.

The vulnerability was successfully verified by generating a CSRF PoC for the email update request and confirming that the victim's email address was changed without intentionally submitting the form.

## Vulnerable URL

https://kzlabs.in/1308.php?action=settings

## Vulnerable Functionality

- Update Email Address

## Steps to Reproduce

1. Log in to the application with an authenticated account.

2. Navigate to the **Settings** section.

3. Locate the **Update Email Address** functionality.

4. Enter a new email address and click **Update Email**.

5. Intercept the request using Burp Suite.

6. Observe that the email update request contains the email address in the request body:

```
new_email=newone@gmail.com
```

7. Copy the request into a CSRF PoC generator.

8. Generate the CSRF Proof of Concept.

9. Test the generated PoC in the browser while the victim is authenticated to the application.

10. The forged request is submitted using the victim's authenticated session.

11. Observe that the victim's email address is changed to the email address specified in the forged request.

12. The application displays a success message confirming that the email address was updated successfully.

https://github.com/user-attachments/assets/a04aed6c-acdb-4d2a-ae18-319d9d9697c9

## Impact

An attacker can force an authenticated victim to change their email address without their knowledge. This may affect account recovery and could contribute to **account takeover** if the attacker can subsequently control or access the changed email address.

## Recommendation

- Implement CSRF tokens for password change requests.
- Validate the CSRF token server-side.
- Use appropriate `SameSite` cookie attributes.
- Require the current password or re-authentication before changing the password.
