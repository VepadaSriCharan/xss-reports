# IDOR — Unauthorized Access to Another User's Order Details

## Summary

The application is vulnerable to an Insecure Direct Object Reference (IDOR) vulnerability in the order viewing functionality.

After registering an account and logging in, the application allowed the authenticated user to access their order details through an `id` parameter in the URL. By modifying the `id` value from the user's own order ID to another order ID, it was possible to access an internal company order without any authorization check.

This demonstrates that the application relies on the object identifier supplied by the client without verifying whether the authenticated user is authorized to access the requested order.

## Vulnerable URL

`https://kzlabs.in/701.php?action=order&id=20`

## Vulnerable Parameter

`id`

## Steps to Reproduce

1. Navigate to:

   `https://kzlabs.in/701.php`

2. Create a new account and log in successfully.

3. Navigate to the **My Orders** section.

4. The application displays the user's orders.

5. Select **View Invoice** for one of the user's orders.

6. The URL contains the following parameter:

   ```text
   https://kzlabs.in/701.php?action=order&id=20
   ```

7. The `id` parameter identifies the order being requested.

8. Change the value of the `id` parameter from:

   ```text
   id=20
   ```

   to:

   ```text
   id=5
   ```

9. The modified URL becomes:

   ```text
   https://kzlabs.in/701.php?action=order&id=5
   ```

10. Access the modified URL while remaining authenticated as the registered user.

11. The application returns the details of order `id=5` even though the order does not belong to the authenticated user.

13. The application also explicitly indicates that the order was accessed without proper authorization checks.

### Result

The application returns another order belonging to an internal company account instead of denying access.

## Impact

An attacker may be able to access other users' or internal orders by modifying the id parameter. This could expose sensitive order, customer, payment, and internal company information. Unauthorized access to such information could result in privacy violations and disclosure of sensitive business data.

## Recommendation

- Implement server-side authorization checks to verify that the requested order belongs to the authenticated user.
- Do not trust the id parameter supplied by the client.
- Return 403 Forbidden when unauthorized access is attempted.
- Implement a WAF as an additional defense-in-depth measure to help detect suspicious parameter manipulation.
