# Authentication Bypass via Client-Side Response Manipulation

## Summary

An authentication bypass vulnerability was identified in the UPS Shipment Administration Portal.

The login functionality relies on a JSON response containing a `status` value to determine whether authentication was successful. By intercepting the server response and modifying `status` from `false` to `true`, while removing the authentication error message, it was possible to bypass the login restriction and gain access to the Admin Panel.

## Vulnerable URL

https://kzlabs.in/201.php?action=login

## Vulnerable Parameter

`status`

## Steps to Reproduce

1. Navigate to the UPS Shipment Administration Portal login page.
2. Enter the following credentials:

```text
Username: admin
Password: admin123
```

3. Intercept the login request using Burp Suite.
4. Forward the request and intercept the corresponding server response.
5. The application initially returns a response similar to:

```json
{
  "status": false,
  "errorMessage": "Username and Password does not match."
}
```

6. Modify the response by changing:

```json
"status": false
```

to:

```json
"status": true
```

7. Remove the `errorMessage` field from the response.
8. Forward the modified response to the browser.
9. The application accepts the modified response and grants access to the Admin Panel.
10. The Admin Panel exposes administrative functionality and sensitive shipment information.

## Impact

An attacker may be able to bypass the application's authentication mechanism by manipulating the login response before it reaches the client. This could allow unauthorized access to administrative functionality and potentially expose sensitive application data and privileged operations.

## Recommendation

- Perform authentication and authorization entirely on the server side and never rely on client-controlled response values to establish an authenticated session.
- Do not trust client-side values such as `status` to determine whether authentication was successful.
- Create a secure server-side session only after the submitted credentials have been successfully validated.
- Implement a Web Application Firewall (WAF) as an additional defense-in-depth measure to help detect suspicious authentication-related requests.
