# Stored HTML Injection in Full Name Field

## Summary

A Stored HTML Injection vulnerability was identified in the **Full Name** field of the GitLab profile settings.

The application allows HTML markup entered into the Full Name field to be stored without proper sanitization or output encoding. When a snippet is subsequently viewed, the stored value is rendered as HTML, allowing attacker-controlled markup to modify the appearance of the page.

## Vulnerable URL

https://kzlabs.in/1204.php

## Vulnerable Field

`Full Name`

## Payload Used

```html
<h1 style="color:red">FULLNAME</h1>
```

## Steps to Reproduce

1. Navigate to the GitLab profile settings page.
2. Go to **Edit Profile**.
3. Test the HTML injection payload in the applicable profile fields.
4. Enter the following payload in the **Full Name** field:

```html
<h1 style="color:red">FULLNAME</h1>
```

5. Save the profile settings.
6. Navigate to the **Snippets** section.
7. Open/view a snippet associated with the account.
8. Observe the **Created By** section at the bottom of the page.
9. The injected HTML from the Full Name field is rendered instead of being displayed as plain text.
10. The word `FULLNAME` is displayed as a large red heading, demonstrating that the supplied HTML was interpreted by the application.

## Proof of Concept

The following payload was entered into the **Full Name** field:

```html
<h1 style="color:red">FULLNAME</h1>
```

## Impact

An attacker may be able to inject arbitrary HTML content through the vulnerable Full Name field. This could allow manipulation of the appearance and content of pages where the stored value is displayed, potentially enabling phishing, UI redressing, misleading content, or other social-engineering attacks against users viewing the affected page.

## Recommendation

- Properly HTML-encode user-supplied chat messages before rendering them.
- Sanitize user-controlled input using a well-maintained HTML sanitization library if HTML formatting is required.
- Avoid directly inserting untrusted input into the DOM using unsafe HTML rendering methods.
- Implement a strict Content Security Policy (CSP).
- A Web Application Firewall (WAF) may be used as an additional layer to detect and block common HTML injection patterns.
