# Local File Inclusion in Resource File Retrieval

## Summary

I identified a Local File Inclusion (LFI) vulnerability in the **Advanced File Manager v3.0** application's resource file retrieval functionality.

The application provides a **Resources** section where a user can enter a filename or file path to retrieve a file from the server. By supplying `/etc/passwd` as the resource path, I was able to access and read the contents of the file directly from the server.

This confirms that the application is allowing user-controlled file paths to be processed without properly restricting access to the intended resource files.

## Vulnerable Field

resource

## Vulnerable URL

https://kzlabs.in/903.php?resource=/etc/passwd

## Steps to Reproduce

1. Open the **Advanced File Manager v3.0** application.

2. Navigate to the **Resources** section.

3. Identify the input field that allows a filename or file path to be entered and retrieved from the server.

4. Enter the following payload:

```text
/etc/passwd
```

5. Submit the request to retrieve the file.

6. Observe that the application processes the supplied file path.

7. The contents of `/etc/passwd` are returned in the **Output** section of the application.

8. The response contains system account information from the underlying server, confirming that local files can be read through the `resource` field.

## Payload Used

```text
/etc/passwd
```

## Proof of Concept

The `/etc/passwd` file was successfully accessed by supplying its path through the `resource` field.

The application returned the contents of the file, including system account information such as:

## Impact

An attacker can read sensitive local files from the server that are accessible to the application's process. Depending on the application's permissions and server configuration, this could expose configuration files, application source code, credentials, environment information, system account information, and other sensitive data.

## Recommendation

- Do not allow users to provide arbitrary filesystem paths.
- Restrict file access to a specific allowlisted directory.
- Ensure the resolved path remains within the intended application directory.
- Reject absolute paths and path traversal sequences where they are not required.
- Deploy a Web Application Firewall (WAF), such as Cloudflare WAF, to help detect and block malicious file-access requests.
