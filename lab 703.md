# IDOR — Unauthorized Access to Another Patient's Confidential Medical Records

## Summary

The application is vulnerable to an Insecure Direct Object Reference (IDOR) vulnerability in the appointment functionality.

After logging in as a patient and accessing an appointment, the `id` parameter was identified in the URL. Changing the appointment ID from `3` to `5` allowed access to another patient's appointment and confidential medical information without proper authorization.

## Vulnerable URL

`https://kzlabs.in/703.php?action=appointment&id=3`

## Vulnerable Parameter

`id`

## Steps to Reproduce

1. Log in to the patient portal using a valid account.

2. Navigate to the **Appointments** section.

3. Open an appointment and observe the URL containing the `id` parameter:

   `https://kzlabs.in/703.php?action=appointment&id=3`

4. Modify the `id` parameter from `3` to `5`:

   `https://kzlabs.in/703.php?action=appointment&id=5`

5. Access the modified URL while authenticated as the current patient.

6. The application displays another patient's appointment information.

7. The exposed information includes confidential medical details such as the patient's name, blood group, symptoms, doctor's notes, and diagnosis.

### Result

The application returned another patient's confidential medical record without verifying whether the authenticated user was authorized to access appointment ID `5`.


## Impact

An attacker may be able to access other users' confidential medical records by modifying the `id` parameter. This could expose sensitive health information, including diagnoses, symptoms, blood groups, and doctor's notes. Unauthorized disclosure of such information could result in serious privacy violations and exposure of sensitive patient data.

## Recommendation

- Implement server-side authorization checks to verify that the requested appointment belongs to the authenticated patient.
- Do not trust the `id` parameter supplied by the client.
- Return `403 Forbidden` when unauthorized access is attempted.
- Implement a WAF as an additional defense-in-depth measure to help detect suspicious parameter manipulation.
