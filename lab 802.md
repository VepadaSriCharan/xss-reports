# Server-Side Template Injection (SSTI) in Welcome Email Personalization

## Summary

I identified a Server-Side Template Injection (SSTI) vulnerability in the **Glovo** application's account creation functionality.

The application accepts a user-controlled **First Name** value during account creation and uses this value in the welcome email template that is rendered server-side before delivery.

By supplying a template expression such as `{{2*2}}` in the **First Name** field and creating an account, the expression was evaluated by the server and the resulting value `4` was reflected in the **Subject** and **Name** fields of the generated welcome email.

This confirms that user-controlled input is being processed as a server-side template expression rather than being treated as plain text.

## Vulnerable Field

First Name

## Vulnerable URL

https://kzlabs.in/802.php

## Steps to Reproduce

1. Open the **Glovo** application.
2. Navigate to the **Create account** functionality.
3. Identify the **First Name** field.
4. Enter the following SSTI payload in the **First Name** field:

```text
{{2*2}}
```

5. Fill in the remaining required account registration fields.
6. Create the account.
7. Observe that the application generates a **Welcome Email** after account creation.
8. Open the email preview.
9. Observe that the supplied template expression in the **First Name** field has been evaluated.
10. The value `{{2*2}}` is rendered as `4` in the email content, confirming server-side template evaluation.

## Payload Used

```text
{{2*2}}
```

## Impact

An attacker may be able to inject and execute template expressions in the server-side template engine. Depending on the template engine, configuration, and available objects, this could lead to sensitive information disclosure, unauthorized access to application data, or potentially server-side code execution.

## Recommendation

- Treat user-supplied template values strictly as data rather than executable template expressions.
- Do not directly evaluate user-controlled input within server-side templates.
- Implement strict input validation for template variables.
- Implement a Web Application Firewall (WAF) to help detect and block common template-injection patterns as an additional layer of protection.
