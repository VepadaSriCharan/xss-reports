# Open Redirect Vulnerability

## Summary

I identified an Open Redirect vulnerability in the LinkDash application.

The application accepts a user-controlled URL through an input field and redirects the user to the supplied destination without properly validating or restricting the target URL.

By supplying an external URL such as `https://bing.com`, the application redirects the browser to the attacker-supplied domain.

## Vulnerable URL

https://kzlabs.in/301.php

## Vulnerable Field

URL input field

## Steps to Reproduce

1. Open the LinkDash application.
2. Navigate to the URL-shortening functionality.
3. Enter the following URL in the vulnerable input field:

```text
https://bing.com
```

4. Submit the request.
5. Observe that the application redirects the browser to `https://bing.com`.

## Payload Used

https://bing.com

## Proof of Concept

The application provides a URL-shortening functionality where a user can submit a long URL to generate a shortened link.

## Impact

An attacker may abuse the open redirect to redirect users from a trusted application URL to an attacker-controlled website. This can be used in phishing attacks and may make malicious links appear more trustworthy.

## Recommendation

- Validate and restrict user-supplied redirect destinations.
- Prefer allowing only trusted, predefined domains or relative paths.
- Reject external URLs when they are not required by the application's functionality.
- Properly validate the URL scheme and destination before performing the redirect.
- Consider implementing a warning page before redirecting users to external domains.
