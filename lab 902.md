# Local File Inclusion in Log Viewer

## Summary

I identified a Local File Inclusion (LFI) vulnerability in the **CMS Pro** application's log viewing functionality.

The application uses the `view_log` parameter to specify the file that should be displayed. By modifying the value of this parameter to `/etc/passwd`, I was able to access and read the contents of the file directly from the server.

This confirms that the application is allowing user-controlled file paths to be processed without properly restricting access to the intended log files.

## Vulnerable Parameter 

view_log

## Vulnerable URL

https://kzlabs.in/902.php?view_log=/etc/passwd

## Steps to Reproduce

1. Open the **CMS Pro** application.

2. Identify the page that uses the `view_log` parameter to display log files.

3. Modify the `view_log` parameter and provide the following payload:

```text
/etc/passwd
```

4. Visit the following URL:

```text
https://kzlabs.in/902.php?view_log=/etc/passwd
```

5. Observe that the application processes the supplied file path.

6. The contents of `/etc/passwd` are displayed in the **Page Content** section of the application.

7. The response contains system account information from the underlying server, confirming that local files can be read through the `view_log` parameter.

## Payload Used

```text
/etc/passwd
```

## Proof of Concept

The `/etc/passwd` file was successfully accessed by supplying its path through the `view_log` parameter.

The application returned the contents of the file.

This demonstrates that the `view_log` parameter can be manipulated to read local files from the underlying server.

## Impact

An attacker can read sensitive local files from the server that are accessible to the application's process. Depending on the application's permissions and server configuration, this could expose configuration files, application source code, credentials, environment information, system account information, and other sensitive data.

## Recommendation

- Do not allow users to provide arbitrary filesystem paths.
- Restrict file access to a specific allowlisted directory.
- Ensure the resolved path remains within the intended application directory.
- Reject absolute paths and path traversal sequences where they are not required.
- Deploy a Web Application Firewall (WAF), such as Cloudflare WAF, to help detect and block malicious file-access requests.
