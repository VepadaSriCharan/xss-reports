# HTML Injection in First Name and Last Name Fields

## Summary

An HTML Injection vulnerability was identified in the **First Name** and **Last Name** fields of the Pentest Community Application.

The application accepts HTML markup in both fields and subsequently includes the supplied values in the confirmation email sent after submitting the application. The injected HTML is rendered by the email preview instead of being displayed as plain text.

## Vulnerable URL

https://kzlabs.in/1205.php

## Vulnerable Fields

- First Name
- Last Name 

## Payload Used

```html
<h1 style="color:red">FIRSTNAME</h1>
```

```html
<h1 style="color:red">LASTNAME</h1>
```

## Steps to Reproduce

1. Navigate to the Pentest Community Application.
2. Locate the **First Name** and **Last Name** fields.
3. Enter the following HTML payload in the **First Name** field:

```html
<h1 style="color:red">FIRSTNAME</h1>
```

4. Enter the following HTML payload in the **Last Name** field:

```html
<h1 style="color:red">LASTNAME</h1>
```

5. Fill in the remaining required fields with valid information.
6. Submit the application.
7. Observe the **Recipient's Inbox — Confirmation Email Preview**.
8. The supplied HTML markup is interpreted and rendered in the email.
9. `FIRSTNAME` and `LASTNAME` are displayed as large red headings, confirming that HTML supplied through both fields is rendered in the generated email.

## Proof of Concept

The following payload was submitted through the **First Name** field:

```html
<h1 style="color:red">FIRSTNAME</h1>
```

The following payload was submitted through the **Last Name** field:


## Impact

An attacker may be able to inject arbitrary HTML content into the confirmation email through the First Name and Last Name fields. This could be abused to manipulate the appearance and content of emails, display misleading information, impersonate trusted content, or facilitate phishing and social-engineering attacks against recipients.

## Recommendation

- Properly HTML-encode user-supplied chat messages before rendering them.
- Sanitize user-controlled input using a well-maintained HTML sanitization library if HTML formatting is required.
- Avoid directly inserting untrusted input into the DOM using unsafe HTML rendering methods.
- Implement a strict Content Security Policy (CSP).
- A Web Application Firewall (WAF) may be used as an additional layer to detect and block common HTML injection patterns.
