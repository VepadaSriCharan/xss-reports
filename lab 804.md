# Server-Side Template Injection (SSTI) in User Profile Fields

## Summary

I identified a Server-Side Template Injection (SSTI) vulnerability in the **Unikrn** application.

The application accepts user-controlled values through the **Nickname**, **First Name**, and **Last Name** fields and uses these values in server-side rendered invitation emails.

By injecting template expressions into these fields and subsequently sending an invitation email, the supplied expressions were evaluated by the server-side template engine. The evaluated results were then reflected in the generated invitation email.

This confirms that user-controlled profile data is being processed as server-side template expressions rather than being treated as plain text.

## Vulnerable Fields

- Nickname
- First Name
- Last Name

## Vulnerable url

https://kzlabs.in/804.php

## Steps to Reproduce

1. Open the **Unikrn** application.
2. Navigate to the **Create account** functionality.
3. Enter the following SSTI payload in the **Nickname** field:

```text
{{5*5}}
```

4. Fill in the remaining required fields and create the account.
5. After logging in, navigate to the **Profile Settings** section.
6. Enter SSTI payloads in the **First Name** and **Last Name** fields.

Example payloads:

```text
{{4*4}}
```

```text
{{7*7}}
```

7. Save the profile.
8. Navigate to the functionality that allows sending an invitation to a friend.
9. Enter a recipient email address.
10. Click **Send Invitation**.
11. Observe the generated invitation email.
12. The injected template expressions are evaluated before the email is delivered.

### Nickname

```text
{{5*5}}
```

### First Name

```text
{{4*4}}
```

### Last Name


## Proof of Concept

The application provides a **Nickname** field during account creation. The following SSTI payload was supplied as the nickname:

```text
{{5*5}}
```

After creating the account, the application displayed the supplied value in the user's profile.

The **First Name** and **Last Name** fields in the profile settings were then tested with the following payloads:

```text
{{4*4}}
```

```text
{{7*7}}
```

<img width="1891" height="593" alt="image" src="https://github.com/user-attachments/assets/d11d9647-0e66-4420-8aa5-52321b28dd67" />


After saving the profile, an invitation was sent to a controlled email address.

The generated invitation email contained the evaluated results of the supplied template expressions. The values were evaluated as follows:

```text
{{5*5}}  → 25
{{4*4}}  → 16
{{7*7}}  → 49
```
<img width="1826" height="945" alt="image" src="https://github.com/user-attachments/assets/2969fa6c-b561-411c-b6f6-ff2ec41f8ba6" />


The invitation email reflected the evaluated values in the recipient's email, demonstrating that the **Nickname**, **First Name**, and **Last Name** values are processed by the server-side template engine.

The successful evaluation of these expressions confirms the presence of a Server-Side Template Injection (SSTI) vulnerability in the affected user-controlled fields.

## Impact

An attacker may be able to inject and execute template expressions in the server-side template engine. Depending on the template engine, configuration, and available objects, this could lead to sensitive information disclosure, unauthorized access to application data, or potentially server-side code execution.

## Recommendation

- Treat user-supplied template values strictly as data rather than executable template expressions.
- Do not directly evaluate user-controlled input within server-side templates.
- Implement strict input validation for template variables.
- Implement a Web Application Firewall (WAF) to help detect and block common template-injection patterns as an additional layer of protection.
