# Server-Side Template Injection (SSTI) in Account Name Field

## Summary

I identified a Server-Side Template Injection (SSTI) vulnerability in the **Uber** application's account functionality.

The application accepts a user-controlled **Full Name** value during account creation and uses this value in account notification emails that are rendered server-side before delivery.

By supplying the template expression `{{5*5}}` in the **Full Name** field and creating the account, the expression was evaluated by the server and the resulting value `25` was reflected in the generated account notification email.

This confirms that user-controlled input is being processed as a server-side template expression rather than being treated as plain text.

## Vulnerable Field

Full Name

## Vulnerable URL

https://kzlabs.in/803.php

## Steps to Reproduce

1. Open the **Uber** application.
2. Navigate to the **Create account** functionality.
3. Identify the **Full Name** field.
4. Enter the following SSTI payload in the **Full Name** field:

```text
{{5*5}}
```

5. Fill in the remaining required account registration fields.
6. Create the account.
7. Observe that the application generates an account notification email.
8. Open the generated email preview.
9. Observe that the supplied template expression in the **Full Name** field has been evaluated.
10. The value `{{5*5}}` is rendered as `25` in the email, confirming server-side template evaluation.

## Payload Used

```text
{{5*5}}
```

The result was displayed in the **Name** field and in the email content of the generated account notification email.

The successful evaluation of the supplied expression confirms that the user-controlled **Full Name** value is processed by the server-side template engine, demonstrating a Server-Side Template Injection (SSTI) vulnerability.

## Impact

An attacker may be able to inject and execute template expressions in the server-side template engine. Depending on the template engine, configuration, and available objects, this could lead to sensitive information disclosure, unauthorized access to application data, or potentially server-side code execution.

## Recommendation

- Treat user-supplied template values strictly as data rather than executable template expressions.
- Do not directly evaluate user-controlled input within server-side templates.
- Implement strict input validation for template variables.
- Implement a Web Application Firewall (WAF) to help detect and block common template-injection patterns as an additional layer of protection.
