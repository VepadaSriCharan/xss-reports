# IDOR — Unauthorized Access to Private User Profile and Confidential Posts

## Summary

The application is vulnerable to an Insecure Direct Object Reference (IDOR) vulnerability in the profile and photo functionality.

While browsing the public gallery, the UUID of another user's photo was exposed. By using the associated user's UUID in the profile URL, it was possible to access the private profile and confidential private content belonging to another user.

## Vulnerable URL

`https://kzlabs.in/704.php?action=profile&uuid=<victim_uuid>`

## Vulnerable Parameter

`uuid`

## Steps to Reproduce

1. Log in to the application using a valid user account.

2. Navigate to the **Explore** section.

3. Open the **Public Gallery** and select a photo belonging to another user, such as Chloe Williams.

4. Observe that the photo page exposes the owner's UUID.

5. Navigate to your own profile and observe that the `uuid` parameter is present in the URL.

6. Replace your own UUID with the victim's UUID:

   `https://kzlabs.in/704.php?action=profile&uuid=<victim_uuid>`

7. Access the modified URL while authenticated as the current user.

8. The application displays the victim's private profile even though the account is marked as **Private**.

9. The victim's private posts are also visible.

10. A confidential private post titled **"Confidential project notes — DO NOT SHARE"** can also be accessed.

## Impact

An attacker can access private user profiles and confidential content by modifying the `uuid` parameter. This can lead to unauthorized disclosure of private posts, profile information, and other sensitive user data.

## Recommendation

- Implement server-side authorization checks to verify that the requested profile and content belong to the authenticated user or are otherwise authorized for access.
- Do not rely on UUIDs as an authorization mechanism.
- Return `403 Forbidden` when unauthorized access to private resources is attempted.
- Avoid exposing sensitive object identifiers where they are not required.
