# HTML Injection Vulnerability

## Summary

An HTML Injection vulnerability was identified in the application's search functionality.

The application reflects the user-supplied search query directly into the search results page without properly encoding or sanitizing the input. This allows an attacker to inject arbitrary HTML markup that is interpreted and rendered by the browser.

## Vulnerable URL

https://kzlabs.in/1202.php

## Vulnerable Field

`Search`

## Payload

```html
<h1 style="color:red">HACKED</h1>
```

## Steps to Reproduce

1. Open the application and navigate to the search functionality.
2. Enter the following payload into the **Search** field:

```html
<h1 style="color:red">HACKED</h1>
```

3. Submit the search query.
4. Observe the search results page.
5. The injected HTML is rendered as a large heading with red text.

## Proof of Concept

The application provides a **Search** field where users can enter search queries.

## Impact

An attacker may be able to inject arbitrary HTML content into the search results page. This could be abused to manipulate the appearance and content of the page, display misleading information, impersonate trusted content, or facilitate phishing and social-engineering attacks.

## Recommendation

- Properly HTML-encode user-supplied chat messages before rendering them.
- Sanitize user-controlled input using a well-maintained HTML sanitization library if HTML formatting is required.
- Avoid directly inserting untrusted input into the DOM using unsafe HTML rendering methods.
- Implement a strict Content Security Policy (CSP).
- A Web Application Firewall (WAF) may be used as an additional layer to detect and block common HTML injection patterns.
