# Open Redirect Vulnerability

## Summary

An Open Redirect vulnerability was identified in the application's logout functionality.

When a user logs out, the application uses the `redirect_to` parameter to determine the destination after logout. The parameter accepts an attacker-controlled URL and can be manipulated to redirect the user to an external domain.

## Vulnerable URL

https://kzlabs.in/304.php?action=logout&redirect_to=https://www.tumblr.com/dashboard

## Vulnerable Parameter

`redirect_to`

## Steps to Reproduce

1. Log in to the application and initiate the logout functionality.
2. Observe the logout request generated by the application:

https://kzlabs.in/304.php?action=logout&redirect_to=https://www.tumblr.com/dashboard

3. Modify the `redirect_to` parameter with the following payload:

https://www.bing.com\@www.tumblr.com

4. Access the modified URL.
5. Observe that the application redirects the browser to:

https://www.bing.com

## Payload

https://www.bing.com\@www.tumblr.com

## Proof of Concept

The application generates the following logout request:

https://kzlabs.in/304.php?action=logout&redirect_to=https://www.tumblr.com/dashboard

The following payload was supplied as the value of the `redirect_to` parameter:

https://www.bing.com\@www.tumblr.com

After processing the request, the application redirected the browser to `https://www.bing.com` instead of the intended destination.

<img width="1818" height="874" alt="image" src="https://github.com/user-attachments/assets/02576c60-07b0-446b-99f7-873f05344508" />

The successful redirection to an attacker-controlled external domain confirms that the `redirect_to` parameter can be manipulated to perform an Open Redirect.

## Impact

An attacker may abuse the open redirect to redirect users from a trusted application URL to an attacker-controlled website. This can be used in phishing attacks and may make malicious links appear more trustworthy.

## Recommendation

- Validate and restrict user-supplied redirect destinations.
- Prefer allowing only trusted, predefined domains or relative paths.
- Reject external URLs when they are not required by the application's functionality.
- Properly validate the URL scheme and destination before performing the redirect.
- Consider implementing a warning page before redirecting users to external domains.
