# IDOR — Unauthorized Access to Another Driver's Earnings

## Summary

The application is vulnerable to an Insecure Direct Object Reference (IDOR) vulnerability in the driver's earnings functionality.

After logging in as a victim and accessing the Earnings section, the `driver_uuid` parameter was identified in the URL. After logging out and logging in as an attacker, replacing the attacker's `driver_uuid` with the victim's UUID allowed access to the victim's earnings information without proper authorization.

## Vulnerable URL

`https://kzlabs.in/702.php?action=earnings_detail&driver_uuid=DRIVER-A1B2-C3D4`

## Vulnerable Parameter

`driver_uuid`

## Steps to Reproduce

1. Log in using the victim account.

2. Navigate to the **Earnings** section and open the earnings details.

3. Observe the URL containing the victim's `driver_uuid`:

   `https://kzlabs.in/702.php?action=earnings_detail&driver_uuid=DRIVER-9E8F-7A6B`

4. Copy the victim's UUID.

5. Log out from the victim account.

6. Log in using the attacker account.

7. Navigate to the **Earnings** section and open the earnings details.

8. Observe that the attacker has a different UUID in the URL:

   `https://kzlabs.in/702.php?action=earnings_detail&driver_uuid=DRIVER-A1B2-C3D4`

9. Replace the attacker's UUID with the victim's UUID:

   `https://kzlabs.in/702.php?action=earnings_detail&driver_uuid=DRIVER-9E8F-7A6B`

10. Access the modified URL while authenticated as the attacker.

11. The application displays the victim's earnings information.

### Result

The attacker was able to access the victim's earnings details.
This confirms that the application does not properly verify whether the authenticated user is authorized to access the requested driver's earnings.

## Impact

An attacker may be able to access other users' or internal orders by modifying the `id` parameter. This could expose sensitive order, customer, payment, and internal company information. **Unauthorized access to such information could result in privacy violations and disclosure of sensitive business data.**

## Recommendation

- Implement server-side authorization checks to verify that the requested order belongs to the authenticated user.
- Do not trust the `id` parameter supplied by the client.
- Return `403 Forbidden` when unauthorized access is attempted.
- Implement a WAF as an additional defense-in-depth measure to help detect suspicious parameter manipulation.
