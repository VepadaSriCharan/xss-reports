# Open Redirect Vulnerability

## Summary

I identified an Open Redirect vulnerability in the LinkDash application.

The application processes the requested URL path in a way that allows an attacker to manipulate the path and cause the browser to redirect to an external domain.

By supplying a specially crafted path containing an external domain, the application redirected the browser to `https://bing.com`.

## Vulnerable URL

https://kzlabs.in/302.php

## Vulnerable Field

URL Path

## Payload Used

```text
////bing.com/?www.omise.co/
```

## Steps to Reproduce

1. Open the vulnerable URL:

```text
https://kzlabs.in/302.php
```

2. Modify the URL path by appending the following payload:

```text
////bing.com/?www.omise.co/
```

3. The resulting URL becomes:

```text
https://kzlabs.in/302.php////bing.com/?www.omise.co/?category=updates&page=1
```

4. Navigate to the modified URL.
5. Observe that the browser is redirected to the external domain:

```text
https://bing.com
```

The successful redirection to an attacker-controlled external domain confirms that the application's redirect functionality can be manipulated through the URL path, resulting in an Open Redirect vulnerability.

## Impact

An attacker may abuse the open redirect to redirect users from a trusted application URL to an attacker-controlled website. This can be used in phishing attacks and may make malicious links appear more trustworthy.

## Recommendation

- Validate and restrict user-supplied redirect destinations.
- Prefer allowing only trusted, predefined domains or relative paths.
- Reject external URLs when they are not required by the application's functionality.
- Properly validate the URL scheme and destination before performing the redirect.
- Consider implementing a warning page before redirecting users to external domains.
