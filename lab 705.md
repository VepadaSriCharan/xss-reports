# IDOR — Unauthorized Access to Another User's Bank Account Details

## Summary

The application is vulnerable to an Insecure Direct Object Reference (IDOR) vulnerability in the account statement functionality.

After logging in as a valid user, the account number was directly exposed through the `acct` parameter. By modifying the account number, it was possible to access another user's bank account details and transaction history without proper authorization.

## Vulnerable URL

`https://kzlabs.in/705.php?action=statement&acct=10003451`

## Vulnerable Parameter

`acct`

## Steps to Reproduce

1. Log in to the application using a valid user account.

2. Navigate to the **Dashboard**.

3. Click on the **Checking Account**.

4. Observe that the account statement URL contains the `acct` parameter:

   `https://kzlabs.in/705.php?action=statement&acct=10003451`

5. Modify the account number to another valid account number, for example:

   `https://kzlabs.in/705.php?action=statement&acct=10003453`

6. Access the modified URL while remaining authenticated as the original user.

7. The application displays another user's account information.

8. The exposed information includes the account holder's name, account number, account type, current balance, and transaction history.

## Impact

An attacker can access other users' bank account information by modifying the `acct` parameter. This can expose sensitive financial information, account balances, and transaction history belonging to other customers.

## Recommendation

- Implement server-side authorization checks to verify that the requested account belongs to the authenticated user.
- Do not rely on account numbers or other identifiers as an authorization mechanism.
- Return `403 Forbidden` when a user attempts to access an unauthorized account.
- Ensure all account-related endpoints enforce proper object-level access control.
