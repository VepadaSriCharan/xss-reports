# Local File Inclusion in File Access

## Summary

I identified a Local File Inclusion (LFI) vulnerability in the **File Access** functionality of the SecureFile Viewer v2.1 application.

The application allows users to enter a filename or file path into the **File Access** field and retrieve the requested file. By supplying an absolute system file path such as `/etc/passwd`, I was able to access and display the contents of a file outside the intended application directory.

This confirms that user-controlled file paths are not being properly restricted, allowing arbitrary local files accessible to the application to be read.

## Vulnerable Field

File Access

## Vulnerable URL

https://kzlabs.in/901.php

## Steps to Reproduce

1. Open the **SecureFile Viewer v2.1** application.

2. Navigate to the **File Access** functionality.

3. In the **File Access** field, enter the following file path:

   ```text
   /etc/passwd
   ```

4. Click the **View File** button.

5. Observe that the application successfully loads the requested file.

6. The contents of `/etc/passwd` are displayed directly in the **File Content** section of the application.

7. The response contains system account information, including entries such as:

   ```text
   root:x:0:0:root:/root:/bin/bash
   daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
   bin:x:2:2:bin:/bin:/usr/sbin/nologin
   www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
   ```

## Payload Used

```text
/etc/passwd
```

## Impact

An attacker can read sensitive local files from the server that are accessible to the application's process. Depending on the application's permissions and server configuration, this could expose configuration files, application source code, credentials, environment information, system account information, and other sensitive data.

## Recommendation

To mitigate this vulnerability:

- Do not allow users to provide arbitrary filesystem paths.
- Restrict file access to a specific allowlisted directory.
- Ensure the resolved path remains within the intended application directory.
- Reject absolute paths and path traversal sequences where they are not required.
- Deploy a Web Application Firewall (WAF), such as Cloudflare WAF, to help detect and block malicious file-access requests.
