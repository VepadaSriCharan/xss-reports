# Stored HTML Injection in Wallet Nickname Field

## Summary

A Stored HTML Injection vulnerability was identified in the **Nickname** field of the Romit wallet application.

The application allows user-controlled nickname values to be stored without proper HTML encoding or sanitization. The stored nickname is subsequently inserted into the wallet invitation email as HTML.

By injecting HTML markup into the nickname field and sending a wallet invitation, the injected markup is rendered by the recipient's email preview instead of being displayed as plain text.

## Vulnerable URL

https://kzlabs.in/1203.php?saved=1#settings

## Vulnerable Field

`Nickname`

## Payload

```html
<h1 style="color:red">HACKED</h1>
```

## Steps to Reproduce

1. Log in to the Romit application and navigate to **Settings**.
2. Locate the **Nickname** field under **Profile Settings**.
3. Enter the following payload into the **Nickname** field:

```html
<h1 style="color:red">HACKED</h1>
```

4. Click **Save Changes**.
5. Observe that the nickname is stored successfully.
6. Navigate to the **Share Your Wallet** section.
7. Observe the **Recipient Email Preview**.
8. The injected HTML from the nickname field is rendered in the email as a large heading with bright red text.

## Impact

An attacker may be able to inject arbitrary HTML content into the wallet invitation email through the stored nickname value. This could be abused to manipulate the appearance and content of emails, display misleading information, impersonate trusted content, or facilitate phishing and social-engineering attacks against recipients.

## Recommendation

- Properly HTML-encode user-supplied chat messages before rendering them.
- Sanitize user-controlled input using a well-maintained HTML sanitization library if HTML formatting is required.
- Avoid directly inserting untrusted input into the DOM using unsafe HTML rendering methods.
- Implement a strict Content Security Policy (CSP).
- A Web Application Firewall (WAF) may be used as an additional layer to detect and block common HTML injection patterns.
