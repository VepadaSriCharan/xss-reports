# XML External Entity (XXE) Injection in Project Creation Functionality

## Summary

An **XML External Entity (XXE) Injection** vulnerability was identified in the project creation functionality.

The application processes new project details using an **XML request body**. By intercepting the request and injecting an external entity referencing a local file, it was possible to make the server read and disclose the contents of the `/etc/passwd` file.

The vulnerability was confirmed through the **Project Name** field.

## Vulnerable URL

https://kzlabs.in/1407.php

## Vulnerable Field

- Project Name

## Steps to Reproduce

1. Navigate to:

```text
https://kzlabs.in/1407.php
```

2. Click on **New Project**.

3. Enter the required project details.

4. Click on **Create Project**.

5. Intercept the request using Burp Suite.

6. Observe that the application sends the project details to the server in an **XML format**.

7. Modify the XML request and add an external entity declaration referencing the local `/etc/passwd` file.

8. Place the external entity reference in the **Project Name** field.

9. Send the modified request.

10. Observe the server response.

11. The response contains the contents of `/etc/passwd`, confirming successful XXE exploitation.

## Payload Used

The following XML external entity declaration was added to the request:

```xml
<!DOCTYPE foo [
  <!ENTITY payload SYSTEM "file:///etc/passwd">
]>
&payload;
```

The server processed the external entity and returned the contents of `/etc/passwd` in the response.

The response disclosed system account information from the server, confirming that attacker-controlled XML input can cause the application to access and disclose local files.

## Impact

The XXE vulnerability allows an attacker to cause the application to read files from the server, resulting in information disclosure. This may expose sensitive configuration files, API keys, application configuration, and other secrets accessible to the application.

## Recommendation
- Disable external entity processing in the XML parser.
- Disable DOCTYPE declarations and external entity resolution where they are not required.
- Use a securely configured XML parser with XXE protections enabled.
- A WAF can provide an additional layer of protection against common XXE payloads.
