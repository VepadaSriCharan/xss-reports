# Server-Side Template Injection (SSTI) in Email Template Personalization Preview

## Summary

I identified a Server-Side Template Injection (SSTI) vulnerability in the **SendStack** application's **Personalization Preview** functionality.

The application provides template variables such as **Recipient Name**, **Email Address**, and **Custom Message**, which are processed when generating the email preview.

By supplying template expressions such as `{{2*2}}`, `{{2*3}}`, and `{{2*4}}` in these fields, the expressions were evaluated by the server and the resulting values were displayed in the **Email Preview** section.

This confirms that user-controlled input is being processed as a server-side template expression rather than being treated as plain text.

## Vulnerable Fields

- Recipient Name
- Email Address
- Custom Message

## Vulnerable URL

https://kzlabs.in/801.php

## Steps to Reproduce

1. Open the **SendStack** application.
2. Navigate to **Templates** and open the **Personalization Preview** functionality.
3. Identify the following input fields:
   - **Recipient Name**
   - **Email Address**
   - **Custom Message**
4. Enter the following SSTI payload in the **Recipient Name** field:

```text
{{2*2}}
```

5. Enter the following SSTI payload in the **Email Address** field:

```text
{{2*3}}
```

6. Enter the following SSTI payload in the **Custom Message** field:

```text
{{2*4}}
```

7. Generate the email preview.
8. Observe that the expressions are evaluated and the resulting values are displayed in the **Email Preview** section.
9. The values `4`, `6`, and `8` are returned respectively, confirming server-side template expression evaluation.

The successful evaluation of arithmetic expressions confirms that user-controlled input is being processed by the server-side template engine, demonstrating a Server-Side Template Injection (SSTI) vulnerability.

## Impact

An attacker may be able to inject and execute template expressions in the server-side template engine. Depending on the template engine, configuration, and available objects, this could lead to sensitive information disclosure, unauthorized access to application data, or potentially server-side code execution.

## Recommendation

- Treat user-supplied template values strictly as data rather than executable template expressions.
- Do not directly evaluate user-controlled input within server-side templates.
- Implement strict input validation for template variables.
- Implement a Web Application Firewall (WAF) to help detect and block common template-injection patterns as an additional layer of protection.
