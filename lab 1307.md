# Cross-Site Request Forgery (CSRF) in Password Change Functionality

## Summary

A **Cross-Site Request Forgery (CSRF)** vulnerability was identified in the password change functionality.

The application does not appear to implement an effective CSRF protection mechanism for password change requests. An attacker can capture a legitimate password change request, generate a CSRF Proof of Concept (PoC), and induce a victim to visit the generated link.

When the victim is authenticated, the forged request is processed using the victim's active session, causing their account password to be changed without their knowledge or explicit interaction with the password change functionality.

The vulnerability was successfully verified by changing the victim account's password through a CSRF attack and confirming that the new password could be used to log in while the previous password was rejected.

## Vulnerable URL

https://kzlabs.in/1307.php

## Vulnerable Functionality

- Password Change Functionality

## Steps to Reproduce

1. Log in to the application using an attacker account.

2. Attacker account credentials used:

   - Email: john@gmail.com
   - Password: john123

3. Navigate to the **Settings** section.

4. Open the **Change Password** functionality.

5. Enter a new password and submit the request.

6. Intercept the password change request using Burp Suite.

7. Copy the intercepted request into a CSRF PoC generator.

8. Generate the CSRF Proof of Concept.

9. Click **Test in Browser** and copy the generated PoC URL.

10. Log in to the application from a separate browser/session using the victim account.

11. Victim account credentials used:

   - Email: armin@mail.com
   - Password: armin123

12. While authenticated as the victim, open the generated CSRF PoC URL in the victim's browser.

13. Observe that the password change request is automatically submitted using the victim's authenticated session.

14. The victim's password is changed without the victim intentionally accessing or submitting the password change form.

15. Attempt to log in using the newly configured password.

16. The login succeeds with the new password.

17. Attempt to log in using the victim's original password.

18. The login fails, confirming that the victim's password was successfully changed through the CSRF attack.

## Impact

An attacker can force an authenticated victim to change their password without their knowledge. This may lead to **account takeover** if the attacker knows the password set through the CSRF request.

## Recommendation

- Implement CSRF tokens for password change requests.
- Validate the CSRF token server-side.
- Use appropriate `SameSite` cookie attributes.
- Require the current password or re-authentication before changing the password.
