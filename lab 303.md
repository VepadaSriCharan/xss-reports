# Open Redirect Vulnerability

## Summary

An Open Redirect vulnerability was identified in the application's URL redirection functionality.

The application contains links to external websites, and clicking the **Visit Page** option generates a request to the following endpoint:

https://kzlabs.in/303.php?url=https%3A%2F%2Fwww.semrush.com%2Ffeatures%2F

The `url` parameter controls the destination of the redirect and can be modified to point to an arbitrary external domain.

## Vulnerable URL

https://kzlabs.in/303.php?url=https%3A%2F%2Fwww.semrush.com%2Ffeatures%2F

## Vulnerable Parameter

`url`

## Payload

https://bing.com

## Steps to Reproduce

1. Open the application and navigate to a page containing external links.
2. Click on the **Visit Page** option.
3. Observe the request generated in the browser's Network tab:

https://kzlabs.in/303.php?url=https%3A%2F%2Fwww.semrush.com%2Ffeatures%2F

4. Modify the value of the `url` parameter to:

https://bing.com

5. Access the modified URL.
6. Observe that the application redirects the browser to:

https://bing.com

## Impact

An attacker may abuse the open redirect to redirect users from a trusted application URL to an attacker-controlled website. This can be used in phishing attacks and may make malicious links appear more trustworthy.

## Recommendation

- Validate and restrict user-supplied redirect destinations.
- Prefer allowing only trusted, predefined domains or relative paths.
- Reject external URLs when they are not required by the application's functionality.
- Properly validate the URL scheme and destination before performing the redirect.
- Consider implementing a warning page before redirecting users to external domains.
